# Continuum remarkable demo — canonical scenario

Working title: **The €250,000 Silence**  
Target master: **3:54**, 1920×1080, 30 fps  
Category: **Fortified Enterprise Fleet**

## The one idea a judge must remember

> The most dangerous agent failure is not a crash. It is an important promise
> quietly becoming nobody's responsibility.

Continuum is not presented as an incident dashboard, a retry engine, or a tour
of Google Cloud services. It is a chain of custody for institutional intent.
The film follows one supplier-onboarding obligation from silent failure to
independently verified completion.

## The remarkable moment

The signature moment happens at the authority handoff, not on the title card:

1. v17 is visibly denied both action and memory.
2. The €250,000 obligation remains open and moves to v18.
3. Two verified facts cross the boundary.
4. Prompt injection, a predecessor secret, stale inference, and revoked memory
   visibly remain behind.
5. v18 immediately resumes the actual supplier-assurance work.

Voice:

> The obligation crosses. Two verified facts cross. A prompt injection, a
> secret, stale inference, and revoked memory do not. The agent is replaceable.
> Its promise is not.

This is the product in one scene. Everything before it creates tension;
everything after it proves the promise was genuinely completed.

## Film rules

- Open on the working product, not a logo or architecture diagram.
- Start exactly one fresh cloud run on camera within the first ten seconds.
- Preserve the run from click through `VERIFIED` as one continuous screen
  recording. Editorial overlays may guide attention but cannot fabricate state.
- Keep the cursor visible and purposeful. It follows new evidence, never circles
  aimlessly, and never remains frozen for more than four seconds during change.
- Label evidence honestly: `CONTINUOUS LIVE RUN`, `SAME-RUN CLOUD PROOF`,
  `RELEASED DERIVATIVE PROOF`, or `REFERENCE ARCHITECTURE`.
- Keep the `.run.app` URL visible at the opening and show native Google Cloud
  evidence later.
- Never type live, expose credentials, show unrelated tabs, or read hashes aloud.
- The public legal-entity example is always labelled `HACKATHON SANDBOX · PUBLIC
  REGISTRY DATA · NO COMMERCIAL RELATIONSHIP`.
- Use three dry lines at most. No joke overlaps a security verdict.
- Target 3:54 and hard-stop at 3:58.

### 2. Detect what did not happen — 0:16–0:40

**Judge payoff**

## Cursor choreography

The cursor always carries meaning:

- click once on `Start live run`;
- point to each newly arrived event as it becomes relevant;
- trace the sequence eligibility → Gemini → policy;
- touch both v17 denials;
- move with the obligation through the context gate;
- visit GLEIF → VIES → Gemini → deterministic admission;
- connect two delivery IDs to one provider resource;
- cross the verifier trust boundary only when narration does;
- point to revision, trace ID and `15/15 PASS` in the proof cutaways.

Use a small 26–30 px soft halo, not a large click animation. The cursor never
rests over text that the viewer must read.

## Transition and highlight language

- Between live stages: no transition; native state change is the transition.
- Between trust boundaries: 4-frame hard cut.
- To architecture or released proof: 300 ms opacity dissolve with the evidence
  slug changing first.
- Important native element: 2 px cyan or green focus outline, 12 px radius,
  12 px breathing room, 220 ms fade in, 300 ms fade out.
- Never crop the cockpit header, URL bar, run ID, or top of a native card.
- Maintain 64 px title-safe and 48 px action-safe margins.

## Final review questions

A reviewer who watches once must be able to answer yes to all of these:

- Did I see a useful agent complete a real multi-step job?
- Did I see the browser start once and then only observe?
- Did Gemini make a causal, bounded decision?
- Did policy—not the model—move authority?
- Did only authorized context cross?
- Did two deliveries produce one scoped effect?
- Did a separate identity issue the final verdict?
- Did I see same-run Google Cloud proof?
- Can I repeat the product in one sentence tomorrow?

The intended one-sentence recall is:

> Continuum keeps an organization's promise alive when the agent responsible
> for it fails.
